# fantermo の振る舞いと，そう決めた理由

fantermo がどう振る舞うかと，その理由をまとめたものです．設定の書き方そのもの（キーの一覧と既定値）は README と設定ファイルのひな形（`crates/fantermo-core/src/config.rs` の `TEMPLATE`）に，コードの構成と処理の流れは [docs/architecture.md](architecture.md) にあります．ここではそれを繰り返さず，なぜそう振る舞うかと，README に書いていない振る舞いの細部を書きます．

## 1. 配布と更新

### 配布物

- `vMAJOR.MINOR.PATCH` のタグを push すると，GitHub Actions が配布物を作って Release に載せます．main への push では検証（fmt，clippy，test）だけを行います．バージョンは workspace の `version` で，タグと食い違えば配布のワークフローが止まります．手順は `.claude/skills/release` にあります．
- 配布物は MSI と zip です．どちらにも `fantermo.exe` と，その隣にブリッジ（`fantermo-bridge.exe` と `fantermo-bridge`）が入ります．
- MSI はユーザー単位で `%LOCALAPPDATA%\Programs\fantermo` に入れ，管理者権限を求めません．スタートメニューの直下に「fantermo」のショートカットを作り，デスクトップのアイコンは作りません．ショートカットの作業フォルダはホームのフォルダです．fantermo はシェルに自分の作業フォルダを渡すので，ショートカットから起動したシェルはホームで始まります．完了の画面の「fantermo を起動する」も同じ作業フォルダで起動します．
- MSI の画面は，開始，進み具合，完了の三つだけです．使用許諾とインストール先の画面は出しません．開始の画面のボタンは「インストール」です（標準の開始の画面の「次へ」の文を変えると，保守の画面の「次へ」も変わるため，開始の画面を別に作っています）．完了の画面の題は，操作（インストール，修復，削除）に合わせて変えます．
- 新しいバージョンの MSI は前のバージョンを置き換えます（`MajorUpgrade`）．古いバージョンを外してから入れ，入れるのに失敗したら古いバージョンを戻します．同じバージョンの別のビルドでも置き換えます（分けると「プログラムと機能」に同じバージョンが二つ並ぶため）．古いバージョンを新しいバージョンの上に入れようとすると，一文を出して止まります．UpgradeCode を変えると上書きできなくなるので，変えません．
- アンインストールでは，MSI が入れたファイル，ショートカット，空になったフォルダを消します．設定ファイル，`state.toml`，ログは消しません．

### アプリの中からの更新

流れは architecture.md の「更新の確認と適用」にあります．

- 確認するのは，「fantermo について…」の「更新を確認」を押したときだけです．起動時や定期的には確認しません．
- 押せるのは，リリースのビルドで，実行ファイルのフォルダが `%LOCALAPPDATA%\Programs\fantermo` のときだけです（`update::can_update`）．MSI の登録は見ていません．判定を誤るとボタンが押せないままになるので，場所だけで決めます．zip を同じフォルダに展開したものも押せます．押せないときは「自動更新は、インストーラでインストールした場合にのみ利用できます」と添えます．
- 取得先はアプリが組み立てます（`latest` のリリースの `latest.json`，`latest.json.sig`，`fantermo.msi`）．`latest.json` から使うのはバージョンと MSI の SHA-256 だけで，書いてある URL は使いません．署名は，取得したバイト列のまま検証してから JSON として読みます．
- バージョンは `MAJOR.MINOR.PATCH` を数として比べます．配布しているバージョンがいまのバージョン以下なら「最新」です．
- 受け取る大きさの上限は，`latest.json` が 64 KiB，署名が 1 KiB，MSI が 200 MiB です．待つ上限は，名前の解決と接続が 10 秒，送受信が 30 秒です．
- 確認している間も「fantermo について…」は開いたままで，ボタンだけを押せなくします．結果のメッセージボックスは「fantermo について…」の上に出します．閉じてしまっていれば，端末のウィンドウの上に出します．
- 更新すると決めたら，MSI をダウンロードして SHA-256 を照合し，同じ実行ファイルのほかの fantermo が動いていれば知らせて続けるかを聞き，「すべてのタブを閉じて…」の確認のあと，外で動く PowerShell のスクリプトに引き渡してからウィンドウを閉じます．
- スクリプトは，fantermo（ほかのものも含む）が終わるのを 300 秒まで待ち，終わらなければ待たずに `msiexec /qn /norestart` で入れます．終了コード 0 と 3010 を成功とし，成功したときだけ fantermo を起動し直します．結果は `%LOCALAPPDATA%\fantermo\logs\update-apply.log` に追記します．`/norestart` は，無人の更新で再起動が始まらないようにするためです．

### バージョンの見せ方

- 「fantermo について…」には `0.1.0` の形で，開発中のビルドは `0.1.0 (dev-<短い SHA>)` の形で見せます．
- ウィンドウのタイトルは `<表示しているタブのタイトル> - fantermo <バージョン>` で，タブのタイトルがなければ `fantermo <バージョン>` です（`window::window_title`）．タブバーのタイトルにはバージョンを付けません．

## 2. 起動とコマンドライン

書き方は README の「コマンドライン」にあります．

- オプションはコマンドラインの先頭でだけ読みます．`fantermo vim --profile x` の `--profile` は `vim` への引数です．引数の並びをシェルの書き方のまま子プロセスへ渡せるようにするためです．
- `--profile <名前>` の名前は，大文字と小文字を含めて完全に一致するものを探します．`--profile` の値が `--` で始まるときは名前がないものとし，その語はオプションとして読み続けます．二度書けば後のものです．`--profile=x` の形は読みません（コマンドの一部になります）．
- 名前がないとき，値がないときは，設定ファイルのエラーと同じく，ウィンドウを開いてから警告を見せ，指定しなかったものとして開きます．警告には設定にあるプロファイルの名前を並べます．起動を止めないのは，打ち間違いで端末が一つも開かないより，開いてから直せるほうがよいからです．
- `--profile` とコマンドを両方書くと，そのプロファイルの接続方式・アイコン・名前で，プロファイルの `command` の代わりにそのコマンドを起動します．そのウィンドウの「新しいタブ」も同じ指定で開きます．

### 起動中の起動

流れは architecture.md の「起動」にあります．

- 起動したプロセスは，同じデスクトップの fantermo のウィンドウを Z オーダーの順（最後に使ったものから）に探し，見つかればそこへタブを足して終わります．タブを足したウィンドウは前面に出します（ダイアログを開いていればそのダイアログ，最小化していれば元に戻します）．
- 渡すのは，実行ファイルのパスと設定ファイルのパス（`FANTERMO_CONFIG` を含む）が同じウィンドウだけです（大文字と小文字は区別しません）．開発中のビルドを起動したときに，インストールした fantermo にタブが足されないようにするためです．
- 管理者として動いているかが違うウィンドウには渡しません．Windows は整合性レベルの低いプロセスからの `WM_COPYDATA` を止めますが，高いほうからは届くので，管理者として起動したものが普通のウィンドウのタブにならないよう，送る側が飛ばします．
- 応答しないウィンドウは飛ばして次へ渡します．待つのはすべてのウィンドウを合わせて 3 秒です（`instance::SEND_TIMEOUT`）．
- 見えていないウィンドウ（起動の途中のもの）は飛ばすので，ほぼ同時に二つ起動すると二つのウィンドウになることがあります．仮想デスクトップの別のほうにあるウィンドウも見つかります．
- ダイアログやメニューを開いている間に届いた起動は，閉じてからタブを足します．表示しているタブに対して働いている処理（貼り付けの編集など）の途中で，表示しているタブが替わらないようにするためです．積んだまま閉じたウィンドウは，自分の実行ファイルを `--new-window` で起動し直して引き継ぎます．
- 足したタブの作業フォルダは，起動したときの作業フォルダです．環境変数は渡しません．
- 受け取った内容は外から来た入力として扱い，形が合わなければ捨てます（`instance::Forwarded::decode`）．

## 3. プロファイルと接続方式

- プロファイルは `[[profiles]]` のテーブルの配列で，既定は最上位の `default_profile`（書かなければ先頭）です．作業フォルダと環境変数は持ちません．
- `profiles` がなければ，最上位の `shell` からプロファイルを一つ作ります．名前は実行ファイルの名前です．`shell` もなければ PowerShell（`powershell.exe -NoLogo`）です．`profiles` と `shell` の両方があれば `profiles` を使い，`shell` は警告します．同じ役割の値を二つ持たないためです．
- `shell` から作るとき，Cygwin の `bin` の下の実行ファイルはブリッジ（`backend = "cygwin"`），`wsl.exe` もブリッジ（`backend = "wsl"`）にし，ほかは ConPTY にします（`Profile::from_shell`）．理由は architecture.md の「Cygwin と WSL の既定をブリッジにした理由」にあります．PATH から探す名前だけのもの（`zsh -l`）と，`wsl.exe` に `-u` などほかのオプションを付けたものは ConPTY のままです．ファイルに書いた `[[profiles]]` は変えません．
- ConPTY で起動するコマンドラインの最初の語が，パスの区切り（`\`，`/`）もドライブ名も含まない名前だけのもの（`powershell.exe`，`cmd`）なら，fantermo が環境変数 `PATH` の項目を前から順に見て探し，見つけた絶対パスの実行ファイルを起動します（`config::find_program_on_path`）．空白を含む名前は `"` で囲みます．囲まなければ最初の空白の前までを名前とします．名前に `.` がなければ，`CreateProcessW` と同じく `.exe` を付けて探します．
- fantermo 自身の作業フォルダ（fantermo を起動したときのフォルダ．タブの作業フォルダとは別）と，fantermo の実行ファイルのフォルダは見ません．`CreateProcessW` に名前だけを渡すとこの二つのフォルダも探すので，fantermo を起動したフォルダ（展開した書庫や共有フォルダなど）に置かれた同じ名前のファイルを起動してしまうためです．同じ理由で，`PATH` の項目のうち空のもの，`.`，相対パスのものも，fantermo の作業フォルダで結果が変わるので見ません．
- 名前だけのコマンドが見つからなければ，ほかの理由で起動できなかったときと同じく起動の失敗とし，理由の文に，どの名前が `PATH` に見つからなかったかを書きます．パスの区切りやドライブ名を含むコマンドは，探さずにそのまま渡します．
- 設定ダイアログでプロファイルを足したときとコマンドラインを書き換えたときは，接続方式を変えません．ブリッジの `command` は相手の側のコマンドラインで意味が違うので，打つたびに接続方式が変わると分かりにくいためです．
- ブリッジの `command` が Windows のプログラム（WSL では `wsl` と `.exe` で終わるもの，Cygwin では `wsl`，`cmd`，`powershell`，`pwsh`）なら，設定ダイアログの入力欄の下に文を出し，ログにも残します（`Profile::windows_program_in_bridge`）．止めはしません．Windows のプログラムをブリッジの中で起動すると ConPTY を通ることになり，ブリッジにした意味がなくなるためです．見るのは最初の語だけです．
- プロファイルの変更は次に開くタブから効きます．開いているタブはそのままです．

### 新しいタブで起動するもの

- 「+」，キーの `new_tab`，メニューの「新しいタブ」は既定のプロファイルを開きます．fantermo を引数つきで起動したウィンドウでは，引数のコマンドラインを開きます．
- 「▾」の一覧（と「+」の右クリック）から選んだプロファイルは，引数があってもそのプロファイルの `command` を開きます．一覧の項目には 1〜9 の番号のアクセラレータを付け，既定のプロファイルに印を付けます．
- 起動できなければ，警告を残してタブを足しません．ブリッジや Cygwin が見つからないとき，ブリッジがエラーで終わったときは，理由を端末に赤い文字で出してタブを残します（architecture.md の「ブリッジ」）．

### ブリッジ

起動のしかたとプロトコルは architecture.md の 4 節にあります．

- `cygwin_root` を書かなければ，`PATH` の項目を順に見て，絶対パスで名前が `bin`（大文字と小文字は問わない）で `cygwin1.dll` と `sh.exe` があるフォルダの一つ上を使います．なければ `C:\cygwin64`，`C:\cygwin` の順に探します．`sh.exe` も見るのは，`cygwin1.dll` を同梱しているだけのアプリのフォルダを掴まないためです．相対パスの項目は，作業フォルダで結果が変わるので見ません．書いた `cygwin_root` に Cygwin がなければ，探さずにエラーにします．
- `command` が一つのコマンドなら，前に `exec` を付けて `/bin/sh -c` に渡します（`bridge::shell_command`）．シェルを親として残さず，Ctrl+C のあとの終了コードがアプリのものになるようにするためです．一つのコマンドとみなすのは，引用の外に `|&;<>()` やバッククォート，改行がなく，先頭の語が `NAME=値` でもシェルの予約語でもないものです．それ以外はそのまま渡します（シェルが親として残ります）．
- 終了コードは，終了の単位の終了コードをそのまま，シグナルなら 128 + シグナルの番号（シェルと同じ）にします．
- 子プロセスへは `TERM=xterm-256color`，`TERM_PROGRAM=fantermo`，`TERM_PROGRAM_VERSION=<Cargo のバージョン>` を渡します（`session.rs` の `CHILD_ENV`）．ConPTY とブリッジで同じです．`TERM_PROGRAM` は `ghostty` や `kitty` にしません．
- WSL の側でブリッジを実行できるのは，既定のマウントで Windows のファイルに実行の権限が付くためです．`/etc/wsl.conf` の `fmask` などで実行の権限を外した環境は扱いません（起動できない理由を端末に出します）．

## 4. タブとタブバー

- タブバーは端末が一つでも常に出します．出し入れで端末の行数が変わらないようにするためです．寸法は端末のフォントによらず，96 DPI のときのピクセル（`tab_bar.rs` の先頭の定数．高さは 26）を DPI に比例させます．端末のフォントを小さくしたときにタブバーまで小さくならないようにするためです．
- 色はシステムの色から作ります（`tab_bar::Palette::from_system`）．ハイコントラストなどの設定に従うためです．Windows 11 の `COLOR_BTNFACE` と白の差は小さいので，背景は `COLOR_BTNFACE` を文字の色へ 15% 寄せ，表示しているタブには縁の線を引きます．アプリのモードを「ダーク」にしてもシステムの色は明るいままなので，タブバーも明るいままです．
- タイトルは Windows の UI のフォント（メッセージのフォント）の 0.85 倍で描き，ピクセルの幅で末尾を「…」にして省略します．省略の位置は，閉じるボタンを出していないタブでも閉じるボタンの手前までで決めます（マウスを載せても省略の位置が変わらないように）．
- タイトルはアプリが付けたもので，なければ「fantermo」です．ConPTY は起動してすぐ子プロセスの実行ファイルのパスをタイトルとして送るので，何もしないシェルではパスになります（Windows Terminal と同じ）．タイトルは出力を流し込むたびに前のものと比べ，変わったときだけ書き換えます．端末のリセット（`ESC c`）でタイトルが消えたときも追えるようにするためです．
- タブの幅は等分で，上限 240，下限 72（96 DPI）です．下限でも入りきらなければ，表示しているタブが見える位置まで並びをずらします．並べ替えはできません．
- 閉じるボタンは，表示しているタブには常に，ほかのタブはマウスを載せたときだけ出します．ボタン（メニュー，閉じる，新しいタブ，▾）は，押したのと同じボタンの上で離したときだけ働きます．タブは押したときに表示します．中ボタンは，押したのと同じタブの上で離すとそのタブを閉じます．タブバーの上の操作は端末へ送らず，ホイールも何もしません．
- 表示しているタブを閉じたら右隣を，右端なら新しい右端を表示します．最後のタブを閉じるとウィンドウを閉じます．子プロセスが終わったタブは閉じ，最後のタブならその終了コードが fantermo の終了コードになります．
- 裏のタブの出力も読み続けて端末に流し込みます．描くのは表示しているタブだけです．
- 届いて端末にまだ流し込んでいない出力に次の分を足すと 64 MiB を超えるなら，流し込むまでそのタブの出力を読みません．アプリの側では書き込みが待たされ，出力が止まります（ほかの端末と同じ）．大量の出力でメモリが増え続けないようにするためです．
- 溜まった出力は少しずつ流し込み，その合間にキー入力，描画，タブの切り替え，閉じる操作を受け付けます．大量の出力を流している間も，タブを閉じたり別のタブへ切り替えたりできるようにするためです．子プロセスが終わったタブは，届いた出力を流し込みきってから閉じます．
- タブのタイトルにプロファイルの名前は使いません．ConPTY が起動してすぐ送るパスとどちらを優先するかを決めていないためです．

### メニュー

- ≡ のメニューは「新しいタブ」「タブを閉じる」，「コピー」「貼り付け」「すべて選択」，「設定…」「設定ファイルを開く」「fantermo について…」，「終了」の順で，区切りの線で分けます．≡ のボタンを隠さないよう，その左下に出します．
- 端末の右クリックとメニューキーのコンテキストメニューは「コピー」「貼り付け」，「すべて選択」，「新しいタブ」「タブを閉じる」です．設定と終了は ≡ にだけ置きます．
- 「コピー」は選択していなければ押せません．「設定…」と「設定ファイルを開く」は，設定ファイルの場所が分からなければ押せません．項目に添えるキーは，その動作に割り当てた最初の組み合わせです（割り当てがなければ添えません）．
- 「設定ファイルを開く」は，設定ファイルを既定のアプリに渡し，失敗したら System32 の `notepad.exe` で開きます（`link_opener`）．
- 「終了」は，タブがいくつあっても確認せずにウィンドウを閉じます．

### ベル

- 音は鳴らさず，画面も光らせません．ウィンドウが前面になければ，前面に来るまでタスクバーのボタンを点滅させます（`FLASHW_TRAY | FLASHW_TIMERNOFG`）．
- 裏のタブで鳴ったら，表示するまでタイトルの前に橙の丸い印を付けます．印はタイトルを省略する前に場所を取り，狭いタブでも消しません．表示しているタブで鳴ったベルには付けません．

### アイコン

- タブのタイトルの左に，プロファイルのアイコンを出します．README の「インストール」の節に書いたとおり，画像がなければプロファイル名の淡い色の正方形に絵を載せて作ります．絵は利用者の環境にある本物のアイコンを実行時に読みます．Cygwin や WSL のアイコンには商標があるので，リポジトリに同梱しないためです．
- 実行ファイルのアイコンは，実行ファイルが自分でアイコンを持つときだけ使います．既定のアプリのアイコンは使いません（`bash.exe` のようにアイコンのないものは `>_` になります）．
- 頭文字を添えるのは，同じ絵になるプロファイルが複数あるときだけです．同じ絵かは読んだファイルのパスで比べるので，`cmd` と `C:\Windows\System32\cmd.exe` は同じ絵です．
- 色は，背景色を淡い青から紫の 10 色の表（`tab_icon::PALETTE`）からプロファイル名のハッシュ（FNV-1a）で選びます．起動のたびに，Rust のバージョンによらず同じ色になるようにするためです．赤・橙・黄は入れていません．淡い色は，絵と頭文字の濃い色とのコントラストを取りつつ，白のタブとも灰色のタブとも見分けられるよう，明るさを両方の間に揃えています．
- fantermo の引数で開いたタブ（プロファイルのないタブ）は，淡い灰青の正方形に `>_` を描きます．
- アイコンはタブを開いたときに決まり，設定を変えても開いているタブのアイコンは変わりません．狭いタブでは，状態を知らせるベルの印を残してアイコンを出しません．

## 5. 入力と操作

### キー

- fantermo が受け持つキーは，コピー（Ctrl+C，Ctrl+Insert），貼り付け（Shift+Insert），コンテキストメニュー（メニューキー，Shift+F10），タブの操作（Ctrl+Shift+T，Ctrl+Shift+W，Ctrl+Tab，Ctrl+Shift+Tab）だけです（`keymap::DEFAULT_BINDINGS`）．Ctrl+V，Ctrl+T，Ctrl+W はシェルへ送ります．
- Ctrl+C と Ctrl+Insert は，選択していればコピーして選択を外し，選択していなければキーをシェルへ送ります．
- キーの割り当ては「このキーはこの動作の候補」までを決め，動作が成り立たなければキーをシェルへ送ります．貼り付け，メニュー，タブを開く・閉じるは押したときだけで，押し続けても繰り返しません（繰り返しのキーはシェルにも送りません）．タブの切り替えは繰り返します．動作に使ったキーは，離したこともシェルへ送りません．
- 割り当てを引くときは Ctrl・Shift・Alt・Win だけを比べ，ロックの状態と左右の別は見ません．
- Alt+F4，Alt+Space，IME が処理中のキーは Windows に任せます．
- キーを打ったら，スクロールバックを見ていても最新の行に戻り，選択も外します．出力が来ても見ている位置は動かしません．
- kitty keyboard protocol で，アプリが「すべてのキーをエスケープコードで報告する」（フラグ 8）を求めていないときは，Caps Lock と Num Lock を修飾キーの数に入れません（`Vt::encode_key`）．仕様は Enter などにもロックの状態を入れるように読めますが，`CSI 13;2u` と比べるアプリが多く，Num Lock を点けたままの Shift+Enter が届かなくなるためです．フラグ 8 のときと，kitty keyboard protocol を使っていないときはそのまま渡します（従来の符号化はテンキーで Num Lock を見るため）．

### 貼り付け

- 改行を含む文字列をアプリが bracketed paste なしで受けるとき（コマンドとして実行される可能性があるとき）は，送らずに編集のダイアログを出します．判断は起動したコマンドの名前ではなく，貼り付ける時点の端末のモードで決めます．`paste.confirm` で，bracketed paste によらず改行を含むときに確認する，確認しない，も選べます．既定の名前が `unsafe` なのは，bracketed paste のときも終わりの印（`ESC [ 201 ~`）を含めば断るためです．
- `paste.confirm_size` 以上の大きさの文字列は，`paste.confirm`，改行の有無，bracketed paste によらず同じダイアログで確認します．大きさは改行を LF にしたあとの UTF-8 のバイト数で数えます（送る中身に近く，ダイアログの文の数字とも同じ）．ダイアログには「大きなテキストを貼り付けようとしています（1.2 MB）。」のように大きさを添えます（1 MB 未満は整数の KB，それ以上は小数第 1 位までの MB）．
- ダイアログの「貼り付け」は，確認したものとして改行ごと送ります．
- 確認しないで送るとき（`never`）は，libghostty-vt の変換のまま送ります．bracketed paste でなければ LF は CR に，ESC や DEL などの制御文字は空白になり，各行がコマンドとして実行されます．bracketed paste の中では終わりの印の ESC も空白になるので，貼り付けの途中で抜けられません．
- クリップボードの CRLF は，貼り付ける前に LF にします．

### マウス

- 選択は，ドラッグ，ダブルクリックで単語，トリプルクリックで行，Alt を押しながらで矩形です．アプリがマウスを求めていても，Shift を押しながらなら選択します．
- 右クリックは，ボタンを離したときにコンテキストメニューを出します．アプリがマウスを求めていればアプリへ送り，Shift を押しながらならメニューです．中ボタンの貼り付けはしません．
- 余白の上は端末の画面の一部とみなし，選択もアプリへの報告も，いちばん近いセルの位置に寄せます．libghostty-vt はセルの外の位置の報告を捨てることがあるので，寄せてから渡します．
- マウスのキャプチャをほかのウィンドウに取られたら，選択のドラッグとスクロールバーの操作を終えます．
- メニューキーと Shift+F10 のメニューは，テキストカーソルのセルの左下に出します（文字を隠さないため）．

### ホイール

- アプリがマウスを求めていなければ，Windows の設定の行数ずつスクロールバックを動かします．
- アプリがマウスを求めていれば，1 ノッチごとにボタン 4・5 の押下として送り，解放は送りません（xterm と同じ）．スクロールバーの上のホイールもアプリへ送ります．
- 代替画面でアプリがマウスを求めていなければ，ホイールをカーソルキーに変えて送ります（`Vt::encode_wheel_as_cursor_keys`）．less や man のようにマウスを使わないアプリでもホイールで動けるようにするためです．アプリが DECSET 1007 を切ればやめます．キーの変換器を通すので，カーソルキーのモードと kitty keyboard protocol に従い，修飾キーは付けません．送る量はスクロールと同じくノッチの行数の設定に従います．
- Shift を押していると，アプリへの報告もカーソルキーも送らず，スクロールバックを動かします．

### スクロールバー

- スクロールバーは自分で描きます．Windows 11 の標準のスクロールバーは，太い場所に細いつまみを描き，幅を細くするとつまみが消えるためです．幅は常に取っておき，スクロールバックの有無で桁数が変わらないようにします．
- つまみは普段は細く，マウスを載せている間とドラッグしている間は太くし，トラックも塗ります．色は端末の背景色を文字の色へ寄せて作るので，配色に従います（`scroll_bar::Palette::from_terminal`）．
- つまみの外を押すと表示している行数だけ動かし，押し続けると 250 ms 後から 50 ms ごとに，つまみがマウスの位置に来るまで送ります（標準のスクロールバーと同じ止まり方）．ドラッグはつまみの中の掴んだ位置を保ちます．右ボタンと中ボタンは何もしません．スクロールバーの上の操作はアプリへ送らず，選択も始めません．
- 代替画面と，スクロールバックのない端末ではつまみを描きません．
- スクロールバックは 10000 行です（`vt.rs` の `SCROLLBACK_LINES`）．

### IME

- IMM32 を使い，変換中の文字列は IME に描かせます（TeraTerm と同じ）．変換中のウィンドウはカーソルの位置に端末と同じフォントで，候補のウィンドウはカーソルのセルを避けて出させます．スクロールバックを見ているときも，実際のカーソルの行を使います．

### リンク

- URL と OSC 8 のリンクは，Ctrl だけを押している間，マウスを載せているリンクに下線を引き，手の形のカーソルにします．Ctrl+クリックで開きます．Ctrl+Alt は AltGr になる配列があるので，Ctrl だけのときに限ります．普段から下線などで示すことはしません．
- 開くのは，押したのと同じリンクの上でボタンを離したときです．リンクの上の Ctrl+クリックは，アプリがマウスを求めていてもアプリへ送りません．
- OSC 8 のリンクがあればそちらを優先します．文字から見つける URL は `http://`，`https://`，`file://`，`mailto:` で始まるもので，ASCII の文字だけからなります．全角の文字や空白で切るのは，日本語の文に続けて書かれた URL を見つけるためです（そのため日本語を含む URL は途中で切れます）．折り返しは前後 64 行までたどります．
- 開いてよいのは `http`，`https`，`mailto`，`file` だけです．`file` はファイルそのものを開かず，フォルダならエクスプローラーで開き，ファイルならエクスプローラーで選んだ状態にします．実行ファイルを指していても実行しないためです．ドライブ名のないパス（Cygwin の `ls --hyperlink` が出す Unix のパス）は開きません．接続先（ホスト）が書かれていて，それが `localhost` でもドライブ名（`file://C:/…`）でもない `file:` は開きません．開くと相手のホストへ接続と認証が起きるためです．

## 6. ウィンドウ

### 大きさの基準

- ウィンドウの大きさを基準にします．フォント，フォントの大きさ，スクロールバーの幅，余白を変えても（設定ダイアログの試し表示でも），ウィンドウの位置と大きさは変えず，いまのクライアント領域で桁数と行数を決め直します．最大化・スナップ・全画面のときも同じです．ウィンドウを決まった位置と大きさに置いて使うためです．
- DPI が変わったときは，Windows が DPI の比で拡大・縮小した大きさに任せます（`WM_GETDPISCALEDSIZE` に答えない）．そのため桁数と行数は，セルの寸法の丸め方によって一つ二つ増減することがあります．流れは architecture.md の「DPI の変更」にあります．
- 最小化しても桁数と行数は変えません．最小化のときに Windows が知らせる大きさ 0 をそのまま使うと，シェルや TUI のアプリへ 1×1 のリサイズが届き，戻したときに折り返しが崩れることがあるためです．
- `state.toml` がないときの最初の大きさは，100 桁 × 30 行が入る大きさです．

### 余白

- 端末の画面の上・下・左・右に同じ余白（`[window] padding`，既定は 96 DPI で 4 ピクセル）を空けます．DPI に比例させます（0 は 0 のまま）．余白には端末の背景色（背景画像があればその上に背景色を重ねたもの）が見えます．
- 右の余白は端末とスクロールバーの間で，スクロールバーはウィンドウの右端にあります．タブバーはウィンドウの幅いっぱいで，上の余白はその下です．
- ウィンドウの大きさがセルの整数倍でないときの端のピクセルは，端末を描く領域の右と下に残ります．

### ウィンドウの状態（`state.toml`）

- 覚えるのはウィンドウの位置・大きさ・最大化だけです．タブや作業フォルダは覚えません．`state.toml` は fantermo が書くファイルで，利用者が手で書くものではありません．起動したときに一度だけ読み，書き換えを見張りません．
- 大きさはピクセルで覚え，ピクセルのまま戻します．違う DPI で起動しても換算せず，桁数と行数はその DPI のセルで入る数になります．大きさを基準にするためです．`dpi` を書いたファイルも読めますが，`dpi` は無視し，書き直すとなくなります．
- 最小化して閉じたときは，普通の状態として書きます．最大化して閉じたときは，最大化と，元に戻したときの大きさを書きます．
- 書くのは，ウィンドウを閉じるとき（× と Alt+F4，≡ の「終了」，最後のタブの終了）と，ログオフ・シャットダウン・再起動で終わらされるときです（architecture.md の「ログオフ」）．一時ファイルに書いてから置き換えるので，途中で止まっても前のファイルは壊れません．同時に複数の fantermo が動いていれば，最後に閉じたものの状態が残ります．
- 読めない（TOML として，型として読めない，UTF-8 でない）ときは `state.toml.broken` に写してから既定の大きさで開きます．原本は動かさず，閉じるときに書き直します．大きさが 0 以下のように使えない値は，警告を残して既定の大きさにします．
- どのモニターにも重ならない位置や，画面より大きい大きさは，Windows が作業領域に寄せます．
- ログオフのときは，ウィンドウを壊さず，端末と子プロセスにも何もしません．セッションのほかのプロセスと一緒に終わらされるので，後始末を足すと終わる途中で止まりうる箇所が増えるだけだからです．`WM_QUERYENDSESSION` は止めずに真を返します．

### タブを閉じるときの片づけ

仕組みは architecture.md の「タブを閉じるとき，ウィンドウを閉じるとき」と「起動直後に閉じると残るプロセス」にあります．利用者から見た決まりは次のとおりです．

- タブを閉じても，fantermo は子プロセスを直接は終わらせません．ConPTY は疑似コンソールを閉じ，ブリッジは標準入力を閉じて SIGHUP を送らせ，シェルとアプリが自分で終わるのを待ちます．
- ConPTY では，閉じてから 5 秒たってもコンソールが残っていれば，そのコンソールに接続しているプロセスと，タブの子孫で接続し終えないまま 3 秒を過ぎたコンソールのプログラムだけを終わらせます．別のコンソールを持つもの（`start` で開いたものなど），どのコンソールにも接続していないもの，ウィンドウのプログラムは終わらせません．タブから起動した別のアプリまで巻き込まないためです．
- Cygwin と WSL では，シェルが終わったあとも前面のプロセスグループが残っていれば，2 秒まで SIGHUP を送り直します．背景のジョブ（`nohup`，`disown`）には送りません．
- ウィンドウを閉じたときは，片づけの途中のタブがあれば，fantermo が終わるのを 10 秒まで待ちます．fantermo が先に終わると，片づけのスレッドも終わるためです．
- fantermo が異常終了したときの片づけはしません．

## 7. 文字の描き方

### 曖昧幅

- East Asian Ambiguous の文字は 1 セルで固定します．理由は architecture.md の「libghostty-vt の取り込み」にあります．
- フォントのグリフがセルより広いとき（Bizin Gothic の ○ や ※ は全角の幅でデザインされている）の描き方を `font.wide_glyph` で選べます．名前を「曖昧幅」ではなく「広いグリフ」としているのは，効くのが曖昧幅の文字に限らず，グリフが割り当てたセルより広いとき全般だからです．2 セルの文字のグリフが 2 セルより広いときも同じに扱います．
  - `shrink`（既定）: 横に縮めてセルに収めます．
  - `clip`: 縮めずにセルの左に置き，はみ出た部分を切ります．Bizin Gothic の ○ は，グリフが全角の送り幅の真ん中にあるので左半分になります．
  - `overflow`: 縮めずにセルの左に置き，右のセルへはみ出して描きます．
  - `overflow_center`: 縮めずにセルの真ん中に置き，左右のセルへ同じだけはみ出して描きます．
- はみ出して描くのはセルの 2 倍の幅までで，それより広いグリフはその幅に縮めます．罫線・ブロック要素・点字など形として描く文字には効きません．
- グリフは背景とカーソルを描いたあとに左の列から描くので，右へのはみ出しは右のセルの文字の下に，左へのはみ出しは左のセルの文字の上に重なります．反転・選択・カーソルの上の文字は，はみ出した部分も文字の色（背景色）で描くので，隣の背景に溶けて見えないことがあります．
- 斜体のようにインクがセルの左右へはみ出すグリフも，切らずに隣のセルへ重ねて描きます（重なり方は上と同じ）．`clip` で切った広いグリフには，はみ出しの余白を足しません．

### アトラスに入りきらないとき

- 1 フレームの文字がグリフアトラスに入りきらないときは，アトラスを空にして組み直し，それでも入らない文字と装飾，タブバーの文字とアイコンだけを飛ばして，入ったものは描きます．画面の左上の行から順に場所を取るので，下の行から欠けます．飛ばした数は警告に残し，前のフレームと同じ数なら繰り返しません．

### 罫線と記号

- 罫線とブロック要素は，フォントに頼らず形として描きます．罫線も曖昧幅の文字なので，全角の幅でデザインされたグリフを縮めるとつながらないためです．
- 点字（U+2800〜U+28FF），Powerline の U+E0B0〜U+E0BF，レガシーコンピューティング記号の U+1FB00〜U+1FB94 と U+1FB9A〜U+1FBAE も形として描きます．それ以外の記号と Nerd Font のアイコンはフォントに任せます．対象と描き方は `boxdraw.rs` と `boxdraw/` のコメントにあります．

### 装飾と点滅

- 下線（5 種），取り消し線，上線を描きます．下線の色の指定がなければ文字の色に従います．取り消し線と上線は常に文字の色です．
- 薄い文字（SGR 2）は前景色を背景色へ半分寄せ（Ghostty と同じ割合），不可視の文字（SGR 8）は文字も装飾も描きません．
- 点滅（SGR 5，6）の文字は 0.5 秒ずつ見せたり隠したりします．隠すのは文字と装飾で，背景は残します．動かすのは，ウィンドウがアクティブで，表示しているタブに点滅で見た目の変わるセルがあるときだけです．アクティブでない間は見せたまま止めます．点滅を止める設定はありません．カーソルは点滅させません．
- `CSI 1;m` のように最後のパラメータが空の SGR は，libghostty-vt の読み方に合わせ，`1` として読みます（ECMA-48 の読み方では `1;0` で，太字が残りません）．fantermo は書き換えません．

## 8. 端末の色

- 配色は `[colors] scheme` の `dark`（既定）と `light` で，背景色・文字の色・16 色をまとめて変えます．`background` と `foreground` で書いた色だけを上書きできます．16 色を一つずつ書く項目と，テーマのまとまりはありません．256 色の残り（16〜255）は libghostty-vt の標準の色です．
- ダークは libghostty-vt の既定の色（背景 #000000，文字 #ffffff，Ghostty の既定の 16 色）です．
- ライトは Windows Terminal の One Half Light を元に，白の背景で読めるよう暗めにした色です（`config::LIGHT_COLORS`）．背景は表示しているタブと同じ白で，タブが端末につながって見えます．明るい色は普通の色より明るく，明るい黒は zsh-autosuggestions などの薄い文字に使われるので白より薄くしています．白と明るい白を文字として読める灰色にしたので，`\e[47m` の背景の上の既定の文字は読みにくくなります．
- カーソルと選択には配色の専用の色を持たせません．カーソルは文字の色（アプリが OSC 12 で変えればその色），選択は文字の色と背景色の入れ替えです．カーソルの色を配色で決めると，`foreground` を上書きしたときにカーソルが背景に溶けうるためです．
- アプリが OSC 4・10・11 で変えた色は，配色を変えても残ります．OSC 104・110・111 で戻すと配色の色になります．問い合わせには配色の色を答えます．
- 配色を変えると，開いているすべてのタブに渡し，すでに出ている文字も新しい色で描き直します．
- スクロールバーと余白は端末の色に従います．タブバーはシステムの色のままです．

## 9. 背景画像

- 新しいタブを開くたびに（最初のタブも），`[[background.images]]` の一覧からランダムに一枚選びます．タブごとに違う画像になります．同じ画像が続けて選ばれることもあります．
- 一覧にはファイル，フォルダ，ワイルドカード（`*` と `?`．パスの最後の部分だけ）を書けます．相対パスは設定ファイルのフォルダが基準です．フォルダは下のフォルダを見ません．フォルダとワイルドカードから選ぶのは拡張子が png，jpg，jpeg，bmp，gif，webp のファイルで，名前で書いたファイルは拡張子によらず候補にします．同じファイルは一度だけ数えます．展開はタブを開くたびにし直すので，フォルダの中身が変わっても次のタブから従います．
- 読めない画像は警告を残して別の候補を選び，全部だめなら画像なしにします．
- 不透明度（`image_opacity`）は画像の不透明度で，1 で画像がそのまま見え，0 で消えます（Windows Terminal と同じ向き）．画像の上に端末の背景色を `1 − image_opacity` の不透明度で重ねて描きます．前の書き方の `opacity`（重ねる背景色の不透明度）は，`1 − opacity` に読み替えます．
- 表示方法（`fit`）と不透明度は，一覧の項目ごとにも書けます．フォルダやワイルドカードに書いた値は，そこから選んだ画像に効きます．同じファイルを二つの項目が出したら，先の項目の値です．
- 画像を敷く範囲はタブバーの下の全体（端末の画面，余白，スクロールバーの列）です．表示方法はこの範囲で計算します．スクロールバーの列にも敷くのは，敷き詰めた画像が右端で途切れて見えないようにするためです．スクロールバーのトラックは，背景画像があればマウスを載せている間とドラッグしている間も不透明度 0.5 で塗って画像を透かします．つまみは不透明です．
- 背景色を持つセル（アプリが背景色を付けた文字，反転，選択範囲）は，その色で塗りつぶします．既定の背景色と同じ色を SGR で付けたセルは，背景色を持たないものとして半透明になります．
- 読み直しで一覧のパスの並びが変わったら，すべてのタブで選び直します．表示方法と不透明度だけが変わったら，選んだ画像のまま描き直します．
- 画像はウィンドウのスレッドで読みます．画面（すべてのモニターを合わせた範囲）を覆える大きさより大きければ縮めて持ち，同じ画像を選んだタブで共にします．`center` と `tile` も縮めた大きさで描きます．どのタブも使わなくなった画像は捨てます．

## 10. 端末の中の画像

- kitty graphics protocol と sixel の画像を端末の中に描きます．ConPTY は APC と DCS を落とすので，届くのはブリッジのタブだけです．
- sixel は kitty graphics protocol の画像に変えて端末に置きます（architecture.md の「バックエンドの出力から描画まで」）．位置の追跡，スクロール，消去，代替画面は kitty の画像と同じ扱いになります．
- sixel は文字より下に置きます．xterm は画像の最後の行にカーソルを置くので，改行しないアプリは画像の最後の行に文字を書きます．文字より上に置くとその文字が隠れるためです．不透明な画像を置いたときは，覆うセルの文字を消します（残すと画像の上に文字が見えるため）．そのため，画像の下のセルの文字はコピーできません．
- sixel を置いたあとのカーソルは，xterm と同じく画像の最後の行の同じ桁です．DECSDM が有効なら画面の左上に置いてカーソルを戻します．
- 文字で上書きしても，画像は残ります．xterm は文字を書いたセルの画像を消しますが，kitty の画像の配置は文字に反応しないためです．`CSI 2 J` では消えます．
- DA1 に sixel の `4` を含めて答え，XTSMGRAPHICS には色 1024，大きさ 4096×4096 と答えます．ConPTY のタブでは DA1 に conhost が答えるので `4` が含まれず，sixel を使うアプリは絵を出しません．
- kitty の画像の転送は，直接の転送（`t=d`）だけを受けます．ファイル・一時ファイル・共有メモリは受けません．アプリに fantermo の読めるファイルを読ませないためと，Cygwin・WSL のパスは fantermo から読めないためです．
- 画像の保管は画面ごとに 320 MB（Ghostty の既定と同じ），テクスチャは合わせて 512 MiB までです．表示している画像は上限を超えても捨てません．
- sixel は，大きさが 4096×4096，中身が 256 MiB，塗る画素の数が 4096×4096×4（重ね塗りを含む）を超えた画像を捨てます．塗る画素の数の上限は，一枚の画像で同じ場所を繰り返し塗り直す仕事を，最大の面積の 4 倍までに抑えるためです．
- アニメーションは表示しているタブだけ進めます．裏のタブは止まり，表示すると続きから進みます．
- 描く順は，背景画像，端末の背景，背景より下の画像，セルの背景，文字より下の画像，カーソル，文字，装飾，文字より上の画像，タブバーとスクロールバーです．

## 11. クリップボードと OSC 52

- アプリからクリップボードへの書き込み（OSC 52，OSC 1337 の Copy，OSC 5522）は常に受けます．空の内容はクリップボードを空にします（xterm と同じ）．
- 読み取りは `[clipboard] read` で決めます（README）．`ask` の確認のダイアログは，既定のボタンが「拒否」で，Esc と × も拒否です．文にはタブの番号とプロファイルの名前，表示しているタブかを入れ，アプリが決められるタブのタイトルは入れません．「このタブでは今後も許可」は，そのタブを閉じるまで効きます．`deny` はタブの許可より強く効きます．
- 確認するのは一度に一つです．同じタブから続けて届いた依頼はまとめて一度に答えます．確認しているタブが閉じたらダイアログを閉じます．拒否したあとにまた依頼が来れば，また確認します．ほかのダイアログを開いている間は開かず，閉じてから開きます．
- 書き込みも読み取りも，選択先（`Pc` の `p`，`s` など）を見ずに Windows のクリップボードへ向けます．Windows Terminal と同じで，Windows には xterm の選択に当たるものがないためです．読み取りの答えの `Pc` と終端は依頼に合わせます．
- 書き込みは 8 MiB まで（libghostty-vt のエスケープシーケンスの長さの上限と同じ），読み取りの答えは 1 MiB までです（`fantermo_core::clipboard`）．上限を超えた読み取りには，アプリを待たせないよう空で答えます．
- 読み取りの答えは，貼り付けと同じく CRLF を LF にします．
- ConPTY は読み取りの依頼を fantermo に届けないので，読み取りを使うならブリッジで接続します．

## 12. 設定ファイル

読み込みと読み直しの流れは architecture.md の「起動」と「設定の読み直し」にあります．

- 置き場所は `%APPDATA%\fantermo\config.toml` です．なければ起動時に，各項目を既定値のままコメントにして並べたファイルを作ります（`TEMPLATE`）．利用者が `#` を消して書き換えるだけで済むようにするためです．作れなければ警告を出して既定値で動きます．
- 書き換えたら読み直します．保存の知らせはまとめ，止んでから一度だけ読みます．エディタは一度の保存で何度も書いたり，別名で書いてから名前を変えたりするためです．
- 項目にエラー（型，範囲，空の値）があれば，その項目だけを前の値のまま（起動時は既定値）にします．編集の途中の打ち間違いでフォントが既定の大きさに戻ったりしないようにするためです．書いていない項目と消した項目は既定値に戻ります．TOML として読めないときは，全体を前の値のまま（起動時は既定値）にします．ファイルが消されたときは既定値に戻し，警告は出しません．
- 警告はメッセージボックスで見せ，行を添えます．項目のエラーの文は英語です（toml のエラーの文が英語のため）．読み直しでエラーがなくなれば，開いている警告を閉じます．別のエラーになれば，開いているものを閉じて新しい文で見せ直します．同じ警告（行番号だけが違うものも）は続けて見せません．保存のたびに同じ警告が出ないようにするためです．
- 古い書き方は，読むたびに今の書き方に読み替え（`config::migrate`），変えたところだけをファイルに書き戻します．読み替えたことはログに残し，ダイアログは出しません．書き戻せなければ，読み替えた中身で動きます．
- 設定ダイアログで書くときも，変えた項目だけを書き換え，コメント，空行，並び，知らないキーは残します（`config_edit` の先頭のコメント）．
- 開発やテストのために，環境変数 `FANTERMO_CONFIG` と `FANTERMO_STATE` で設定ファイルと `state.toml` の場所を差し替えられます．

### フォント

- `font.family` のどのフォントも見つからなければ，既定の並び（Bizin Gothic，BIZ UDゴシック，Consolas）から探します．
- 読み直しや設定ダイアログで変えたフォントを使えなければ，前のフォントのままにします．そのとき同時に変えた `font.wide_glyph` も前のままで，前のフォントの設定が「前の値」になります．
- フォントの大きさと `font.wide_glyph` を変えても，ウィンドウの大きさは変えません（6 節の「大きさの基準」）．

### キーと色の設定

- `[keys]` は書いた組み合わせだけを既定の割り当てに重ねます．組み合わせの名前はキーボード上の位置（libghostty-vt のキーの名前）で，配列によらず同じキーを指します．`"none"` は割り当てを外してシェルへ送ります．同じ組み合わせを書き方を変えて二度書いたら，後の行を警告して飛ばします．
- `[colors.tab_bar]` と `[colors.scroll_bar]` は書いた色だけを既定の色に上書きします．既定の色はシステムの色や端末の色から決まるので，ひな形の値は Windows 11 の既定とダークの配色のときの例です．

## 13. 設定ダイアログ

- ≡ の「設定…」で開きます．ページは外観，背景，動作，プロファイル，キー，色です．項目と設定ファイルのキーの対応は `settings_dialog.rs` にあります．
- 変えた項目は，その場で端末に反映します（入力欄は打ち終えて 400 ms たってから）．設定ファイルを読み直したときと同じ道を通るので，ウィンドウの位置と大きさは変えません．「OK」は書いて閉じ，「適用」は書いて開いたまま，「キャンセル」（Esc，×）は最後に書いたとき（書いていなければ開いたとき）の設定に戻して閉じます．
- 書くのは，最後に書いたとき（または開いたとき）から値が変わった項目だけです．比べる相手はファイルではなく開いたときの設定なので，ファイルにエラーの値があっても，ダイアログで触らなければその行は残ります．既定値に戻した項目は，既定値のコメントの行に戻します．ただし，色と `default_profile` は既定値を一つの値で書けないので，それまでの値をコメントにします．ひな形から作ったファイルは，色と `default_profile` のほかは，変えてから戻すとひな形と同じ中身に戻ります．
- 読めない入力はエラーの文を出して反映せず，OK と適用ではその入力欄（見えていないページなら，そのページへ移って）にフォーカスを移して書きません．
- モーダルです．開いている間は端末のウィンドウは入力を受けませんが，出力と描き直しは続きます．開いている間は設定ファイルを読み直さず，閉じてから読み直します．適用したあとに編集を続けているとき，書いた中身で編集中の反映を上書きしないためです．保存したあとは，閉じてから必ず読み直します．
- 開いている間に最後のタブが終わってウィンドウが閉じたら，ダイアログも閉じます．
- フォントの一覧は，等幅の標準の太さのフォントだけを日本語の名前の順に並べます．選んだフォントを `family` の先頭に置き，それまでの並びから同じ書体を除いて後ろに続けます．
- キーのページで読み取った組み合わせがほかの動作に割り当ててあれば，割り当て直すかを聞きます．修飾キーなしの Esc は読み取りをやめる操作なので，割り当てられません．
- 色のページの既定の色は，編集中の配色から決めます．
- 背景のページのファイルとフォルダは，絶対パスで足します．

## 14. ログ

- 開発中のビルドはコンソールに，リリースのビルドは `%LOCALAPPDATA%\fantermo\logs\fantermo.<年-月-日>.log` に出します．古いファイルは 14 個まで残します．水準は既定で `info` で，`RUST_LOG` で変えられます．
- 書き込みは同期です．`std::process::exit` や強制終了で溜めた分を失わないためです（ログの量は少ない）．
- ログの時刻とファイルの日付は UTC です．fantermo を複数起動すると同じファイルに追記します．
- リリースのビルドで起動に失敗したら（メッセージループに入る前の失敗），メッセージボックスで知らせ，ログのフォルダを添えます．パニックの内容もログに残します．

## 15. アプリのアイコン

- 黄色の角丸の背景に，裾を波にした黒い画面と黄色の `%` を描いた図案です．`%` は文字ではなく形として描いています（`assets/icon/`）．24 ピクセル以下では，線を太くした小さい用の図案を使います．
- ICO は 16〜256 ピクセルの 9 サイズで，256 ピクセルだけ PNG です．作り直しは `./tools/icon.sh` です．
- ウィンドウのアイコンは DPI に合う大きさを付け，DPI が変わったら付け直します．ダイアログのタイトルバーにはアイコンを出しません（Windows の標準のダイアログと同じ）．
